# 挂号系统稳定性与功能完善设计

## 目标

在不更换 Servlet + MyBatis + JSP/HTML 架构、不改变现有数据库业务语义的前提下，完成可访问业务页面的功能闭环修复，消除错误跳转、乱码、无效控件和接口响应不一致问题，并保持预约、就诊记录、权限与审计的既有安全边界。

## 范围与边界

- 仅修改本仓库 `C:\Users\ivanr\Desktop\Hospital_system_new\Hospital_system` 中的文件。
- 不执行 `git commit`、`git push`、重写历史或修改远程仓库配置。
- 保留旧功能；不以删除历史页面或接口掩盖问题。旧页面若仍由主流程访问，必须有可用的跳转、错误提示或安全的禁用说明。
- 不改变账号、预约、病历、医嘱或审计日志的既有数据结构，除非在确认业务缺陷后增加向后兼容的数据库迁移。
- 所有新增或修复的动态响应必须使用 UTF-8；JSON 端点必须返回 `application/json;charset=UTF-8`。

## 已确认事实与根因

1. 当前 `master` 基线包含预约生命周期、病历/医嘱、认证、CSRF 和审计模块，自动测试 112 项通过；问题集中在新模块与遗留页面/接口并存时的边界。
2. `EncodingFilter` 只设置请求编码，未在过滤链前统一设置响应编码；遗留 Servlet 中还存在 `text/html`、`text/json`、`test/json` 等不规范 JSON Content-Type。因此中文 JSON 可能被浏览器按错误编码解释，前端也可能无法按 JSON 解析。
3. 多个仍存在的 HTML/JSP 模板保留空链接、`javascript:void(0)` 和 `archive/index.html` 占位跳转。必须先确认是否由可达入口引用，再将可达入口改为业务路由或明确禁用，不改动第三方静态资源。
4. `SearchServlet` 未验证 `keyword`；直接请求且参数缺失时会把 `null` 传入 `String.contains`，形成服务端异常风险。其他输入端点也需按相同标准统一参数校验和错误返回。

## 设计

### 1. 公共 Web 响应契约

- `EncodingFilter` 在调用下游前设置请求和响应的 UTF-8 编码，并为未明确声明 Content-Type 的响应提供兼容的 UTF-8 文本默认值；业务 Servlet 仍须明确声明自己的 JSON 或 HTML 类型。
- 为 JSON 响应建立或复用统一的写出辅助方法，保证状态码、`success`、`code`、`message` 和 Content-Type 一致。前端可预期读取同一错误结构。
- 所有从浏览器输入得到的标识符、分页参数与搜索关键词都先校验，再进入 Service/Mapper；无效输入返回 400 JSON，不抛出 500。

### 2. 页面路由与可访问页面

- 建立“可达页面”判定：从首页、患者中心、医生中心、管理员中心、目录和业务页能点击或脚本导航到的页面属于修复范围。
- 患者路径必须可从科室搜索进入医生目录，选择医生和排班后进入预约；取消、改期、病历查看须停留在患者域且显示清晰的业务错误。
- 医生路径必须可从预约列表进入当前医生自己的就诊记录，完成接诊后保留可读病历与医嘱；无权和无数据状态显示业务提示，不显示空白页或原始异常。
- 管理员路径必须可访问审计查询页，并以角色限制数据读取。过期或不应继续使用的遗留页面不能通过主菜单或主要操作入口跳转过去。
- 可达模板中的占位链接替换为正确的应用上下文路径、真实功能链接，或改为语义明确且无导航行为的按钮。非业务宣传/第三方模板内容不作为功能承诺。

### 3. 预约、就诊与审计闭环约束

- 保持预约状态机：仅合法状态可取消、改期、开始接诊与完成接诊；错误状态给出具体原因。
- 保持病历草稿和定稿规则：医生只能操作自己的预约；草稿允许保存，定稿校验必填诊断、方案、医嘱说明，定稿后不可被草稿覆盖。
- 保持安全边界：未登录为 401，角色或资源越权为 403，写操作需 CSRF；业务成功与失败审计均不得暴露密码、病历正文、身份证号等敏感内容。

### 4. UI 与样式

- 以可访问、可点击、可读为准则修复业务页面的表单控件、错误提示、空状态和溢出；不重做当前 Docpro 视觉主题。
- 日期、时段、状态、中文姓名和医疗文字必须在 UTF-8 页面中正确展示；选择控件不得依赖不必要的横向/纵向滚动才能看到核心选项。

## 验收标准

1. `mvn test` 通过，新增测试覆盖每个新修复的边界；MySQL 集成测试未配置时允许明确跳过，不能误报成功。
2. 主要患者、医生、管理员页面没有可达的空跳转、`archive` 占位跳转或原始 JSON/异常页面；错误均为用户可理解的提示。
3. 对科室搜索缺参、非法 ID、未登录、角色越权、CSRF 缺失、预约非法状态均返回预期 HTTP 状态和 UTF-8 JSON。
4. 在测试数据库/演示数据下，患者预约→改期/取消、医生开始接诊→保存草稿→定稿、患者查看病历、管理员查看审计日志形成可验证闭环。
5. `mvn package` 生成 WAR 成功；本任务不部署、启动 Tomcat 或提交 Git。
