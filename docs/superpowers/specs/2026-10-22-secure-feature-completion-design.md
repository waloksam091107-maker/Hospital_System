# 挂号系统安全功能补全设计

**日期：** 2026-10-22  
**目标目录：** `C:\Users\ivanr\Desktop\Hospital_system_new\Hospital_system`  
**目标：** 在保留预约、接诊、病历、医嘱和审计闭环的基础上，完成当前被停用或只保留历史页面的基础业务功能；所有新增写操作必须以会话身份、角色授权、POST、CSRF、事务和审计为边界。  
**本轮明确不做：** 短信验证码、邮件验证码、未登录找回密码、真实第三方支付。

## 1. 背景与约束

现有项目已具备患者预约、医生排班与接诊、病历草稿/定稿、病历医嘱和管理员审计日志等主链路。旧的注册、资料编辑、基础数据维护、公告维护、订单和充值接口中，部分会信任请求参数中的身份或允许 GET 写数据，因此已由 `LegacyUnsafeWritesDisabledFilter` 与 `LegacyOrdersDisabledFilter` 停用。

本次不重新启用这些旧接口。新功能采用新的受保护入口，旧接口继续返回 410，避免历史链接绕过授权边界。仅修改目标目录；不修改旧目录、不提交或推送 Git。

## 2. 方案选择

采用“新安全入口 + 页面迁移”的方案：

1. 保留旧写入口的停用状态；
2. 新建按资源职责划分的门户接口；
3. 前端页面改用新接口并携带 CSRF 令牌；
4. 写操作在服务层按事务写入业务数据和成功审计；失败操作记录脱敏失败审计；
5. 增加 OceanBase 兼容迁移、单元测试、Servlet 契约测试和页面导航测试。

这样既不让旧页面重新暴露不安全逻辑，也不要求重写已有预约和病历闭环。

## 3. 功能范围

### 3.1 账户与个人资料

- 开放仅限患者的公开注册，账号、身份证号等唯一性由服务层校验；医生和管理员只能由管理员创建。
- 新增本人资料读取与更新接口。患者、医生、管理员仅可修改本人允许编辑的资料；管理端可维护必要的基础账户资料。
- 头像上传使用当前会话身份确定归属，限制文件大小和图片 MIME 类型，并使用服务端生成文件名，不信任客户端指定的用户编号或路径。
- 已登录修改密码维持现有安全入口；未登录找回密码和短信/邮件验证码不在本轮范围。

### 3.2 管理员基础数据与公告

- 管理员可维护医生、患者、科室层级和职称；创建医生或管理员时由服务端建立对应账户数据。
- 科室删除前检查下级科室和医生引用；职称删除前检查医生引用；删除冲突返回可读错误，避免破坏关联数据。
- 公告支持管理员创建、编辑、删除、发布/下线；普通用户只能查询已发布公告。
- 管理页使用新的 `/portal/admin/...` 接口，所有写请求使用 POST 并提交 CSRF 令牌。

### 3.3 余额与模拟充值

- 预约扣费、取消释放号源但不退款的现有规则保持不变。
- 新增仅患者本人可使用的模拟充值：金额必须为正数、限制单次与累计合理范围，写入余额流水并审计。
- 新增 `balance_transactions` 表，记录充值、预约扣费及未来退款扩展所需的金额、类型、关联预约和时间；不接真实支付网关，页面明确标注“模拟充值”。

### 3.4 医生端和预约/病历闭环收口

- 医生主页“排班表”必须是可访问的真实链接，而不是由模板导航保护脚本拦截为“暂未开放”。
- 保留排班、预约列表、开始接诊、病历草稿、病历定稿和医嘱的一条主路径；清除或替换任何指向被停用 `/orders/*` 旧写入口的活动菜单。
- 医生不能操作其他医生的排班、预约或病历；患者不能读取草稿或其他患者的病历。

### 3.5 安全、审计与部署

- 新写接口统一执行 Session 认证、角色授权、CSRF 与 HTTP 方法限制；禁止以表单或查询参数中的 actorId 决定权限。
- 成功业务写入和成功审计必须处于同一数据库事务；失败审计不记录密码、身份证、病历正文、医嘱正文或充值敏感参数。
- OceanBase DDL 使用 MySQL 兼容语法；Docker 部署继续使用忽略的 `.env.oceanbase`，不复制密码或数据卷。

## 4. 接口与数据设计

| 模块 | 新入口（规划） | 权限 |
| --- | --- | --- |
| 患者注册 | `POST /portal/accounts/patient-register` | 匿名，CSRF/输入校验 |
| 本人资料 | `GET/POST /portal/profile` | 当前登录用户 |
| 本人头像 | `POST /portal/profile/avatar` | 当前登录用户 |
| 模拟充值 | `GET/POST /portal/balance/recharge` | 当前患者 |
| 管理员基础资料 | `/portal/admin/doctors`、`/patients`、`/departments`、`/professional-titles` | ADMIN |
| 管理员公告 | `/portal/admin/announcements` | ADMIN |
| 公告读取 | `GET /announcements/list`、`/details` | 公开，仅已发布 |

服务端实际 URL 可以在实施时按既有 servlet 映射冲突做小范围调整，但不得复用已停用的旧写入口。

`balance_transactions` 至少包含：`transaction_id`、`patient_id`、`appointment_id`（可空）、`transaction_type`、`amount`、`balance_after`、`created_at`、`note`。对 `patient_id + created_at`、`appointment_id` 建索引。

## 5. 错误处理

- 未登录：401；角色不匹配：403；资源不存在：404；旧写入口：410。
- 输入错误、金额错误或关联约束：400；重复账号或重复基础数据：409；版本或余额冲突：409。
- 前端为上述状态显示中文业务提示，不将数据库异常或堆栈返回浏览器。

## 6. 测试与验收

每一项实现采用测试先行：先添加会失败的服务/Servlet/页面契约测试，再实现最小功能使其通过。验收包括：

1. 患者注册与三角色登录；
2. 本人资料和头像仅本人可写；
3. 管理员完成医生、患者、科室、职称、公告的 CRUD，非管理员收到 403；
4. 患者模拟充值后余额流水、预约扣费和审计一致；
5. 患者预约/改期/取消、医生排班/接诊/病历医嘱全链路继续可用；
6. 旧不安全写入口仍为 410；
7. `mvn test`、WAR 构建、Docker Compose 校验及容器运行态验证均通过。
