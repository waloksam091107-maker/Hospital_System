# 就诊记录与医嘱

## 目标

让一次处于 `IN_PROGRESS` 的预约只能由所属医生填写一次正式就诊记录；保存记录、保存医嘱和将预约改为 `COMPLETED` 必须在同一个数据库事务中完成。患者只能查看自己的已完成记录和医嘱，不能修改它们。

## 约束

- 保持 Java 8、Servlet、MyBatis 和 MySQL 8 架构；不引入 Spring。
- 以 `appointments` 为权威归属来源；禁止客户端提交医生或患者 ID 来决定权限。
- `medical_records.appointment_id` 必须唯一；一条医嘱属于一条就诊记录。
- 正式提交至少需要诊断；诊疗方案、医嘱说明和处方项目可为空。
- 旧的 `/appointments/complete` 不再允许绕过记录直接完成接诊；医生页面改为进入就诊记录页面。
- 所有新写接口使用既有登录会话、医生/患者角色校验和 `X-CSRF-Token`。

## 验收

1. 非所属医生、非 `IN_PROGRESS` 预约、重复提交和缺少诊断均不会创建记录或改变预约状态。
2. 成功提交后医生和患者读取到同一条记录及全部医嘱，预约状态为 `COMPLETED`。
3. 任一步数据库写入失败时记录、医嘱和预约状态均回滚。
4. 医生预约列表的“完成接诊”进入记录页；患者记录页只展示本人数据。
