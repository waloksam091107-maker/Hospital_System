# 权限、安全与审计

## 目标

把当前系统的新挂号、排班、就诊记录接口统一在登录会话、角色授权、CSRF 和审计边界内，并将新创建/更新的账号凭据改为 BCrypt。

## 约束

- 使用 `org.mindrot:jbcrypt`；数据库迁移新增可空 `password_hash`，旧明文仅允许在本人下一次成功登录时验证一次并立即升级为 BCrypt 后清空。
- 未登录访问受保护接口返回 JSON 401；角色错误返回 JSON 403；所有写请求要求 CSRF。
- 新增审计日志，记录登录成功/失败、预约状态写入、排班写入、就诊记录提交；不得记录密码、完整病历正文或身份证号。
- 保持登录、注册页面和现有 `SessionIdentity` 会话键兼容；公开查询页面不得因安全过滤被阻断。
- 旧 `orders/*` 写接口在新医嘱启用后必须禁用，避免请求参数越权和 `MAX(id)+1` 竞争。

## 验收

1. BCrypt 的哈希校验和旧密码登录后升级可由单元测试证明；响应 JSON 不包含密码/哈希。
2. 未带 CSRF 的排班、预约、病历写入均返回 403，带令牌的合法请求可通过。
3. `/orders/*` 返回 410 并提示使用就诊医嘱；其余新接口拒绝跨角色访问。
4. 每项规定操作有一条脱敏审计记录，管理员可只读查询日志。
