# 审计入口及兼容性说明

| 入口 | 角色 | 成功审计 | 失败审计 |
| --- | --- | --- | --- |
| `/appointments/book` | 患者 | 与预约、号源和余额同事务；目标是新预约主键 | 独立事务 |
| `/appointments/cancel`、`/appointments/reschedule` | 患者 | 与状态和号源同事务；改期分别记录新旧预约，数据库的 `previous_appointment_id` 关联两者 | 独立事务 |
| `/appointments/start` | 医生 | 与接诊状态同事务 | 独立事务 |
| `/schedules/create`、`/schedules/update`、`/schedules/delete` | 医生 | 与排班及号源同事务；目标为排班主键 | 独立事务 |
| `/medical-records/draft`、`/medical-records/finalize` | 医生 | 与病历、医嘱及预约状态同事务；目标为预约主键 | 独立事务 |
| `/password/reset` | 本人 | 验证并锁定账号，密码与成功审计同事务 | 独立事务 |
| `/auth/login` | 全部角色 | 会话建立后独立记录；旧明文密码升级与升级事件同事务，审计失败时不登录 | 独立记录；日志不可用时服务器告警 |

失败日志不含请求参数原文。审计库不可用时独立失败记录无法保证落库，但会写入不含异常明细的服务器告警；业务成功日志写入失败将阻止相应数据库变更提交。登录会话和登录成功日志不属于同一个数据库事务，不能声称原子性。当前未发现后端注销接口。

编码、外层审计、鉴权和 CSRF 过滤器通过 `WEB-INF/web.xml` 按该顺序显式配置；请求级标记防止多层重复记录失败。仍需在实际 Tomcat 中覆盖不同拒绝路径进行回归验证。

关键操作新生成的成功和失败事件使用统一动作名称。按这些动作查询时兼容能明确对应到单个入口的旧动作名称；历史上仅记录 `_MEDICAL-RECORDS` 等无法区分草稿与提交的事件不能可靠归类，仍可使用其原动作名单独查询。旧明文密码升级失败另记 `PASSWORD_UPGRADE` 失败；登录失败也单独记录，失败日志不可用时输出脱敏告警。

## 暂时停用的旧写入口

`LegacyUnsafeWritesDisabledFilter` 对其枚举的旧写入口返回 410，包含公开注册（所有角色）、旧管理员删除预约、旧科室/医生/患者资料及头像写入、菜单和新闻管理。部分旧接口使用 GET 写入，或从请求参数信任操作人编号；不能安全沿用。对应只读页面不在停用列表中。这些功能需另行实现授权、CSRF、事务审计后才能恢复；它们不是本次已完成的功能。旧 `/orders/*` 入口沿用既有停用规则。

此说明不构成所有历史代码或部署环境的安全认证；发布前必须逐一验证实际映射、角色及接口响应。
