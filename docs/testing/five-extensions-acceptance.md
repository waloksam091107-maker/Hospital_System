### 本轮新发现并修复

停诊时段 `,` 或 `AM,,` 原先会被 Java 默认 `split` 丢弃末尾空值，造成无有效时段的申请被创建，或异常格式被静默接受。现保留分割后的空字段并校验每项，错误请求返回 400，且不写申请、通知或成功审计。新增 `ClinicExtendedValidationTest`，先观察到两项失败，再修复并通过定向与全量回归；真实 HTTP 也验证这两类输入均被拒绝。

正常页面操作不生成上述异常参数，本次补上接口边界校验。所有本轮已执行的功能场景通过，未发现尚未修复的功能阻塞；本记录不代表对真实业务库完成部署验收。

## 测试中修复的问题

1. 撤班时已完成预约占用的时段仍可能留有开放容量，现改为保留历史和占用量，同时关闭其余号源。
2. 医生撤回待审核申请被错误要求再次填写审核原因，现可直接撤回。
3. 停诊患者在时段结束后可能被误记为爽约，现由服务端拒绝。
4. 过号恢复在时间相同或 OceanBase 时间戳仅保留整秒时可能插到队首，现使用持久化候诊历史的递增编号决定入队顺序，保留原预约号。
5. 原预约列表没有投影停诊标记，现与门诊页面一样显示已批准的停诊提示。
